# OpenScreen — Technical Specification

An open-source macOS screen recorder in the spirit of Screen Studio / ScreenCharm:
record your screen (and soon an iPhone/iPad over USB), then get a polished,
auto-edited video — smooth cursor, smart zoom, styled background, captions —
without touching a timeline unless you want to.

## Goals

- **Fidelity target:** get as close as possible to Screen Studio's output quality
  and workflow, using only public Apple APIs and permissively-licensed code.
- **Headline differentiator:** wired iPhone/iPad capture (USB) as a first-class
  recording source, alongside display and window capture.
- **Native:** Swift 6 + SwiftUI, ScreenCaptureKit, AVFoundation, CoreMedia.
  No Electron, no GPL dependencies.

## Reference feature matrix (researched 2026-09-25)

| Capability | Screen Studio | ScreenCharm | OpenScreen |
|---|---|---|---|
| Display / window / region capture | yes | yes | yes |
| iPhone/iPad over USB | no | yes (spike) | **yes — headline** |
| Webcam overlay | yes | yes | yes |
| System + mic audio | yes | yes | yes |
| Auto-zoom on clicks | yes | yes | yes |
| Cursor smoothing / hide system cursor | yes | yes | yes |
| Motion blur on fast camera moves | yes | partial | yes |
| Styled backgrounds (gradient/image/wallpaper) | yes | yes | yes |
| Timeline editor (trim, split, speed) | yes | basic | yes |
| Captions (on-device transcription) | yes | yes | yes |
| Vertical / social export presets | yes | yes | yes |
| 4K MP4 / HEVC export | yes | yes | yes |
| Shareable link / cloud | yes | no | no (v2) |

## Architecture

SwiftPM multi-module package is the buildable core; a thin Xcode app shell
(generated by xcodegen from `project.yml`) embeds it. Agents add files inside
`Sources/<Target>/` — nobody hand-edits a `.pbxproj`, so parallel work merges
cleanly.

```
AppFeature (SwiftUI shell)
  RootView → SourcePicker → RecordingController → EditorView
  AppState: central coordinator (@MainActor ObservableObject)
    ├── CaptureKit  — SCK display/window, system+mic audio, webcam, USB iOS, event taps
    ├── CursorKit   — samples → smoothed path, zoom keyframes
    ├── RenderKit   — compositor + preview pipeline
    ├── EditKit     — clips / split / trim / speed
    ├── ExportKit   — AVAssetWriter, 4K/vertical presets
    └── CaptionsKit — Speech transcription → cues
OpenScreenCore — models, geometry, project bundle IO (pure Swift, fully testable)
```

### OpenScreenCore

- `Recording`: captured asset reference (video file + cursor track + events + audio).
- `Project`: the editable document — source recording, clips, zoom keyframes,
  style (background/padding/corner radius/shadow), captions, export settings.
  Codable; a `.openscreen` document is a JSON bundle.
- `Clip`: a timeline segment → `[trim range] × speed` into the source.
- `ZoomKeyframe`: {time, center (normalized), scale} — output camera over time.
- `CursorSample`: {time, position (normalized), kind: move/click-down/click-up/drag}.
- `Geometry`: output-canvas sizing, normalized→pixel mapping, keyframe
  interpolation (`cameraRect(at:)`) with smoothstep easing.
- `RecordingBundle`: read/write the `.openscreen` JSON document.

### CaptureKit

- `DisplayRecorder`: `SCStream` on the chosen display/window/region →
  `AVAssetWriter` (screen video) + system audio track + mic track.
- `CameraRecorder`: `AVCaptureSession` webcam feed → separate movie file.
- `IOSDeviceRecorder`: USB iPhone/iPad via `AVCaptureDevice` continuity-type
  device (same path QuickTime uses) — spike first, behind feature flag.
- `CursorMonitor`: `NSEvent` global+local monitors + high-frequency timer
  (`~120 Hz`) sampling `NSEvent.mouseLocation` → `[CursorSample]`.
- Contracts expose `RecordingInputs` (sources, rects, URLs) → `RecordingBundle`.

### CursorKit

- `CursorSmoother`: Catmull-Rom resampling of raw samples → uniform ~60 fps
  path; velocity-aware dwell detection.
- `ZoomPlanner`: cluster click events (time+space) → `ZoomKeyframe`s
  (zoom in ~0.2 s before click, hold through interaction, ease back).
- Tunables: smoothing window, cluster radius/duration, max zoom scale.

### RenderKit

- `Compositor`: CIImage/CGImage pipeline — fill background → project camera
  rect from zoom keyframes → draw screen frame (rounded, shadowed) →
  motion-blur samples when camera velocity is high → draw software cursor
  → webcam PiP overlay.
- `PreviewRenderer`: realtime preview for the editor (same code path as export,
  lower resolution / cadence).
- `ExportRenderer`: frame-accurate offline pass → `AVAssetWriter` + audio mux.

### EditKit

- `Timeline`: ordered `Clip`s; total duration = Σ(clip length / speed).
- Operations: `trim`, `split(at:)`, `setSpeed`, `remove`, `reorder`.
- `split` divides a clip at timeline time into two clips (tested).

### ExportKit

- Presets: `original`, `landscape1080`, `portrait1080x1920`, `square`,
  `4k` (HEVC) — canvas size + layout rules (camera PiP corner for vertical).
- `Exporter`: RenderKit frames + audio tracks → MP4/MOV via `AVAssetWriter`.

### CaptionsKit

- On-device `SFSpeechRecognizer` transcription of the mic/system mix →
  timestamped `CaptionCue`s; rendered as burn-in text by RenderKit or
  sidecar `.srt`.

### AppFeature

- `AppState` — single `@MainActor` coordinator wiring all kits.
- `SourcePickerView` — display/window/region/USB-device chooser + webcam toggle.
- `RecordingController` — countdown, menu-bar status item, stop → produce
  `RecordingBundle`, open editor.
- `EditorView` — player (PreviewRenderer), timeline (EditKit), zoom/style/
  captions inspectors, export button → ExportKit.

## Recording pipeline

1. User picks sources → `CaptureKit` records screen (+ camera) to temp files
   while `CursorMonitor` samples cursor/click events to JSON.
2. On stop: build `RecordingBundle` (assets + cursor track + metadata).
3. `CursorKit` turns raw samples into a smoothed path + proposed zoom keyframes.
4. Editor opens the `Project`; user tweaks clips/zoom/style/captions.
5. `ExportKit` renders every frame through `Compositor` and muxes audio.

## Constraints & acceptance

- **Acceptance gate per module:** `swift build` + `swift test` green, and
  `xcodebuild` succeeds for the app target.
- **TCC reality:** real screen/USB capture needs user-granted permissions;
  VM testing uses synthetic frames/samples. Contracts are designed so a
  `SyntheticRecorder` can drive the full pipeline.
- **No GPL/transitive GPL**; permissive deps only. Prefer zero third-party deps.
